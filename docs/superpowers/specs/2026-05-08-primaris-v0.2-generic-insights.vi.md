## Hướng đi mới

v0.1.0 gắn primaris với 1 user (Bach) và 1 nguồn dữ liệu (`.imperium/runs/<ticket-id>/log.md`). Chạy được, nhưng không portable. v0.2.0 biến primaris thành **AI Engineering OS dùng chung** — bất kỳ Claude Code user nào cũng install được, fill cấu hình riêng, và dùng như self-coaching loop.

Hai thay đổi cấu trúc:

1. **Identity generic** — không hardcode tên user. Plugin ship template; mỗi user fill tại first-run.
2. **Cawl đọc `/insights`** — Cawl chuyển nguồn chính sang report của Claude Code built-in `/insights` (`~/.claude/usage-data/report.html`). Report aggregate 21 ngày session metrics, friction patterns, project areas, suggestions cụ thể — đúng rubric Cawl cần. Ticket-pipeline run artifacts vẫn dùng được nhưng làm supplement, không phải primary.

Doctrine, levels rubric, và prime-directive playbook đã generic sẵn — không đổi.

## Scope (chỉ v0.2.0)

**Trong scope**

- Cawl rewrite: input chính là `~/.claude/usage-data/report.html`. Workflow extract metrics từ HTML sections của report.
- `/level-check` rewrite: kiểm freshness của report (mtime ≤ 7 ngày). Nếu cũ/thiếu, instruct user chạy `/insights` trước. Sau đó spawn Cawl.
- User-data path: `~/.primaris/growth-plan.md` (và file user khác sau này). Resolve qua env `PRIMARIS_HOME` (default `~/.primaris`).
- `growth-plan.template.md` ship trong plugin. `bach-growth-plan.md` xóa.
- Levels rubric mở rộng: thêm subsection **Roadmap** cho mỗi level (Readiness signals / Upgrade actions / Common blockers).
- README và doctrine de-Bach. `marketplace.json` cập nhật description.
- Bump version 0.1.0 → 0.2.0.
- Thêm entry v0.2.0 vào ROADMAP.

**Ngoài scope (để sau)**

- Phase 2 — Prime Directive enforcement (skills `investigate`, `repro-first`, `scope-guard`). Như cũ.
- Phase 3 — Hard hooks. Như cũ.
- Phase 4 — Workflow library. Như cũ.
- Auto-run `/insights` từ trong `/level-check` (slash command không invoke slash command khác — user phải tự gõ).
- Cawl render eval report ra HTML. Markdown thuần.
- Multi-user trên cùng máy. 1 user / 1 `PRIMARIS_HOME`.

## Kiến trúc

### Thứ tự ưu tiên data source

Cawl đọc theo thứ tự, dùng cái nào có:

1. **Primary**: `~/.claude/usage-data/report.html` — output của Claude Code `/insights`. Bắt buộc cho v0.2.0 default flow.
2. **Supplement**: `.imperium/runs/<ticket-id>/{state.json,log.md}` — cho per-ticket eval khi chạy ticket-pipeline. Optional.
3. **Reference**: `$PRIMARIS_HOME/growth-plan.md` — targets của user. Nếu thiếu, Cawl fallback default từ `growth-plan.template.md` và in 1-line note nhắc user chạy init flow (xem "Init flow" bên dưới).

Nếu primary thiếu hoặc cũ hơn 7 ngày, `/level-check` halt với message rõ ràng yêu cầu user chạy `/insights` trước rồi re-run.

### Chiến lược parse `report.html`

Report là HTML có cấu trúc với `id` và `class` attributes ổn định:

| Section | Anchor | Cawl map sang |
|---|---|---|
| Stats row | `class="stats-row"` (Messages / Lines / Files / Days / Msgs/Day) | Volume metrics (input thô cho level scoring) |
| At-a-glance | `class="at-a-glance"` | Framing ban đầu (working / hindering / quick wins) |
| `What You Work On` | `id="section-work"` | Project/domain breadth (Level 2 / 3 signal) |
| `How You Use Claude Code` | `id="section-usage"` | Orchestration patterns (Level 3 / 4 signal) |
| `Impressive Things You Did` | `id="section-wins"` | Strength evidence |
| `Where Things Go Wrong` | `id="section-friction"` | Anti-signals + Tenet violation candidates |
| `Existing CC Features to Try` | `id="section-features"` | Capability gaps |
| `Suggested CLAUDE.md Additions` | `class="claude-md-section"` | Context-engineering signal (Level 2 indicator) |
| `New Ways to Use Claude Code` | `id="section-patterns"` | Forward growth direction |
| `On the Horizon` | `id="section-horizon"` | External feature awareness |

Cawl extract qua Bash + Python regex (`re` only — không cần HTML parser bên thứ 3). File 67 KB parse trong vài millisecond.

### Quy tắc map Level

Cawl map evidence từ `report.html` sang levels rubric (`playbooks/ai-engineering-levels.md`) bằng heuristic:

- **Level 2 (Context Engineer)** — `Suggested CLAUDE.md Additions` không rỗng (CLAUDE.md đang được duy trì) = positive; "context piecemeal" trong friction section = anti-signal.
- **Level 3 (Advanced Context Engineer)** — friction section nhắc "subagents", "gate review", "ticket-pipeline" = positive; "Prompt is too long" mid-pipeline = anti-signal (single-thread overrun).
- **Level 4 (Hermes Engineer)** — at-a-glance / wins nhắc "parallel observer agent", "self-correcting workflow"; thiếu = neutral, không phải negative.
- **Tenet violation candidates** — friction `Premature implementation before approach validation` = Tenet 1 (Prime Directive); `edits reapplied N times` = scope-discipline gap (Tenet 2 candidate).

Quy tắc map ghi trong subsection "Roadmap" mới của `ai-engineering-levels.md` từng level — Cawl cite rubric line by line trong eval reports.

### Layout user-data

```
$PRIMARIS_HOME/                            # default ~/.primaris/
├── growth-plan.md                         # current state + targets của user (copy từ template lúc init)
└── eval/                                  # Cawl ghi report ở đây
    ├── 2026-05-08-level-check-30d.md
    └── ...
```

Plugin location vẫn read-only:

```
plugins/primaris/
├── playbooks/
│   └── growth-plan.template.md            # ship as template, không edit per user
└── eval/                                  # legacy v0.1.0 location, giữ trống cho backward-compat
```

Cawl ghi report mới vào `$PRIMARIS_HOME/eval/`, không vào plugin tree. `plugins/primaris/eval/` vẫn tồn tại (với `.gitkeep`) để layout v0.1.0 valid trong các doc tham chiếu cũ — nhưng v0.2.0 reports không vào đó nữa.

### Init flow

Pure doc-driven, không command mới trong v0.2.0:

1. User install plugin qua marketplace.
2. README "First-run flow" hướng dẫn:
   ```bash
   mkdir -p ~/.primaris/eval
   cp plugins/primaris/playbooks/growth-plan.template.md ~/.primaris/growth-plan.md
   $EDITOR ~/.primaris/growth-plan.md   # fill in name, current level, targets
   ```
3. User chạy `/insights` 1 lần trong session Claude Code bất kỳ.
4. User chạy `/level-check 7d` từ session bất kỳ.

Slash command `/primaris init` tương lai (Phase 2 candidate) sẽ tự động hóa step 1–3. Ngoài scope v0.2.0.

### Backward compatibility

- v0.1.0 Cawl đọc `playbooks/bach-growth-plan.md`. v0.2.0 xóa file. User upgrade từ v0.1.0 phải chạy init flow.
- v0.1.0 Cawl ghi vào `plugins/primaris/eval/`. v0.2.0 ghi vào `$PRIMARIS_HOME/eval/`. Report cũ giữ nguyên (Cawl đọc làm historical context nếu có), report mới vào location mới.
- Ultramarines `/ticket-pipeline` auto-fire Cawl không đổi.

## Component design

### `agents/cawl.md` — Cawl rewrite

Persona, Iron Law, Tools section giữ. **Inputs** và **Workflow** rewrite để:

- Document priority data source (như trên).
- Thay reference `state.json` / `log.md` bằng `report.html` làm primary path.
- Thêm parsing block: snippet Bash + Python `re` nhỏ — Cawl invoke nhất quán. Snippet document trong agent file.
- Giữ per-ticket và period mode, nhưng redefine "period" theo data span của `report.html` (report span fixed window — thường ~21 ngày).
- Cập nhật report templates để cite `report.html` section IDs làm evidence reference.
- Thay reference `playbooks/bach-growth-plan.md` bằng `$PRIMARIS_HOME/growth-plan.md`.

### `commands/level-check.md` — `/level-check` rewrite

Frontmatter, doctrine note, read-only nature giữ. **Flow** rewrite:

1. Resolve `PRIMARIS_HOME` (default `~/.primaris`).
2. Check `~/.claude/usage-data/report.html` tồn tại.
   - Thiếu → halt: "Run `/insights` first, then re-run `/level-check`." Exit clean.
   - mtime > 7 ngày → halt: "Report is stale (last refreshed YYYY-MM-DD). Run `/insights` to refresh, then re-run." Exit clean.
3. Check `$PRIMARIS_HOME/growth-plan.md` tồn tại.
   - Thiếu → in 1-line warning: "No growth plan at $PRIMARIS_HOME/growth-plan.md. Cawl will use defaults. Run init flow to personalise (see plugin README)."
4. Spawn Cawl với `report_path` và optional `growth_plan_path`.
5. Cawl trả report path + console summary.
6. Print summary verbatim. Echo `Full report: $PRIMARIS_HOME/eval/<filename>`.

Empty state và Examples sections cập nhật tương ứng.

### `playbooks/growth-plan.template.md` — thay `bach-growth-plan.md`

Generic placeholder, không content riêng cho Bach. Sections giữ:

- Header + tagline + `Last updated:` placeholder.
- `## Current state` — placeholder cho level + best-evidence + weakest-evidence.
- `## Strengths to preserve` — bullet trống, hint fill từ `/insights` `Impressive Things You Did`.
- `## Weaknesses to fix` — bullet trống, hint fill từ `/insights` `Where Things Go Wrong`.
- `## 30-day targets (review by YYYY-MM-DD)` — placeholder bullets.
- `## 90-day targets (review by YYYY-MM-DD)` — placeholder bullets.
- `## Cawl's working assumptions` — giữ nhưng 4 item Bach-specific thay bằng example valid stable preferences. User tự thêm preferences riêng.

### `playbooks/ai-engineering-levels.md` — thêm Roadmap subsection

Mỗi level (0–5) thêm 1 subsection block sau `Anti-signals`:

```markdown
**Roadmap to Level N+1**

- *Readiness signals* — behaviour cụ thể chỉ dấu user sẵn sàng claim level kế.
- *Upgrade actions* — 3–5 hành động concrete trong 7–30 ngày tới.
- *Common blockers* — pattern lặp kéo user thụt lùi.
```

Mục đích: human readable ("làm sao lên level?") + machine readable (Cawl cite trực tiếp trong recommendations).

### `PRIMARIS_DOCTRINE.md` — de-Bach nhỏ

Boundary table hiện ghi `Cawl + Bach`. Đổi thành `Cawl + the user`. Không thay đổi khác.

### `README.md` (primaris) — full de-Bach rewrite

Section giữ nhưng rewrite:

- Title vẫn "Personal AI Engineering OS" — generic.
- Why this exists — phrasing generic về engineer dùng AI.
- Components table — vẫn 7 row, nhưng row `Growth plan` reference `$PRIMARIS_HOME/growth-plan.md` (file user) và `playbooks/growth-plan.template.md` (template).
- Composition with ultramarines — không đổi.
- First-run flow — rewrite với 4 step init (mkdir / cp template / edit / run /insights / run /level-check).
- Phase scope — số phase giữ.
- Versioning — Current version: `0.2.0` (2026-05-08 — Phase 1.5: generic + insights-driven).

## Risks và mitigations

| Risk | Mitigation |
|------|-----------|
| Cấu trúc HTML của `/insights` đổi giữa version Claude Code, parsing vỡ. | Parse qua anchor `id` và `class` ổn định; fallback text-only extraction nếu structured fail; in `NOT FOUND` per missing section thay vì crash. |
| User máy mới chưa có `report.html`. | `/level-check` halt với instruction rõ chạy `/insights` trước. Không silent fail. |
| User chưa chạy init flow → không có `growth-plan.md`. | Cawl dùng default từ template; `/level-check` in warning. Eval vẫn produce (mức personalisation thấp hơn). |
| `~/.primaris/` ngập sau vài tháng weekly check. | Report có date trong filename; user prune thủ công. v0.3.0 candidate: archive flag. |
| Máy share nhiều user. | Ngoài scope. Env `PRIMARIS_HOME` cho advanced user redirect; document trong README. |
| Report v0.1.0 cũ ở `plugins/primaris/eval/` orphan. | Cawl đọc làm historical context nếu có. Không auto-delete. User chuyển sang `~/.primaris/eval/` thủ công. |

## Migration từ v0.1.0

Cho user (gồm Bach) đang chạy v0.1.0 hôm nay:

1. Pull v0.2.0 commits.
2. `mkdir -p ~/.primaris/eval`
3. `cp plugins/primaris/playbooks/growth-plan.template.md ~/.primaris/growth-plan.md`
4. Edit growth-plan mới với content trong `bach-growth-plan.md` (file đó bị xóa bởi v0.2.0).
5. Chạy `/insights` 1 lần.
6. Chạy `/level-check 7d`.

Migration document trong v0.2.0 entry của `ROADMAP.md` và README primaris.

## Success measure cho v0.2.0

Sau 4 tuần chạy v0.2.0:

- ≥1 user khác Bach đã install primaris và produce ít nhất 1 Cawl eval report.
- ≥4 Cawl eval report cite `report.html` section ID cụ thể làm evidence.
- Flow `/insights`-driven không regress acceptance criteria nào của v0.1.0.

Nếu 3 signal trên hold, Phase 2 (Prime Directive enforcement) start trên base v0.3.0.
